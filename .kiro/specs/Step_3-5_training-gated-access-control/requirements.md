# Requirements Document

## Introduction

This feature implements Training-Gated Access Control (Phase 3.5) for AlcoaBase, adding a strict compliance enforcement layer that requires users to both pass an AI-generated comprehension quiz AND complete their training task before gaining access to regulated documents. The current system (Phase 3.3) only checks for a completed training task via `TrainingRecord`. Phase 3.5 introduces a quiz attempt tracking system, enforces quiz passage as a prerequisite for task completion, and updates both the frontend `TrainingGateGuard` and backend `check_training_gate` to verify quiz pass status alongside task completion. Quiz questions already exist in `TrainingContent` (generated by the training content generator); this feature adds the interactive quiz-taking flow, answer submission, scoring, and pass/fail enforcement.

## Glossary

- **Quiz_Attempt**: A database record representing a single attempt by a user to answer all quiz questions for a specific training content. Stores individual answers, score, pass/fail result, and timestamps.
- **Quiz_Service**: The backend service responsible for evaluating quiz submissions, computing scores, determining pass/fail status, and persisting quiz attempt records.
- **Quiz_API**: The set of backend API endpoints for submitting quiz answers (`POST /api/training/quiz/submit`) and retrieving quiz results (`GET /api/training/quiz/results/{content_id}`).
- **Quiz_Taking_UI**: The frontend interactive component where users answer quiz questions from the training content, submit answers, and view results.
- **Passing_Score**: The minimum percentage of correct answers required to pass the quiz, configured as 80% (4 out of 5 questions, or equivalent ratio rounded down).
- **Training_Gate_Guard**: The existing React Router wrapper component (from Phase 3.3) that blocks navigation to training-gated documents, updated in this phase to also verify quiz pass status.
- **Training_Service**: The existing backend service managing training tasks and records, updated in this phase to reject task completion when the quiz has not been passed.
- **Training_Content**: The existing data structure storing AI-generated quiz questions, procedural steps, safety points, and summaries for an SOP version.
- **Training_Store**: The existing Zustand state store for training operations, extended in this phase with quiz attempt state and quiz gate checking.
- **API_Client**: The fetch wrapper at `src/frontend/src/lib/apiClient.ts` handling authentication, token refresh, tenant headers, and the `X-Change-Reason` audit header.
- **Content_ID**: The identifier for training content, formatted as `{sop_document_uuid}_v{sop_version}`.

## Requirements

### Requirement 1: Quiz Attempt Data Model

**User Story:** As a system, I want to persist quiz attempt records in the database, so that quiz pass/fail status can be verified for access control enforcement and audit compliance.

#### Acceptance Criteria

1. THE Quiz_Service SHALL store each quiz attempt as a `QuizAttempt` record with the following fields: `id` (primary key), `user_id` (foreign key to users), `content_id` (string, max 255 characters, referencing the TrainingContent), `sop_document_uuid` (string, max 36 characters, indexed), `sop_version` (string, max 20 characters), `answers` (JSON field mapping question_id to the user's selected answer, maximum 50 entries), `score` (integer representing the number of correct answers, constrained to 0 <= score <= total_questions), `total_questions` (integer representing the total number of questions in the quiz, minimum value 1), `passed` (boolean indicating whether the score meets or exceeds the Passing_Score threshold), `attempted_at` (datetime with timezone, server-default to current UTC time), and `company_id` (foreign key to companies).
2. THE Quiz_Service SHALL compute the `passed` field as true if and only if `score >= ceil(total_questions * 0.8)`, where `ceil` denotes rounding up to the nearest integer (e.g., for 5 questions the minimum passing score is 4; for 3 questions the minimum passing score is 3).
3. IF `total_questions` is less than 1, THEN THE Quiz_Service SHALL reject the quiz attempt and not persist a record, because a valid quiz requires at least one question.
4. THE Quiz_Service SHALL allow unlimited quiz attempts per user per content_id, storing each attempt as a separate record to maintain a complete audit trail.
5. THE Quiz_Attempt model SHALL include the `AuditMixin` to enable SQLAlchemy-Continuum versioning, which automatically records all INSERT operations in a corresponding `quiz_attempts_version` table for ALCOA+ compliance.

### Requirement 2: Quiz Submission API Endpoint

**User Story:** As a user, I want to submit my quiz answers to the backend for evaluation, so that my comprehension is assessed and my pass/fail status is recorded.

#### Acceptance Criteria

1. WHEN a user submits quiz answers, THE Quiz_API SHALL accept a POST request to `/api/training/quiz/submit` with a JSON body containing: `content_id` (string, required), `user_id` (integer, required), and `answers` (object mapping question_id strings to selected answer strings, required). The request SHALL require the `X-Change-Reason` header as enforced by the audit middleware.
2. WHEN the Quiz_API receives a valid submission, THE Quiz_Service SHALL retrieve the training content for the given `content_id`, compare each submitted answer against the `correct_answer` field of the corresponding `QuizQuestion` using exact string matching (case-sensitive), compute the score as the count of correct answers, determine pass/fail using the 80% threshold, persist a `QuizAttempt` record, and return a response containing: `attempt_id`, `score`, `total_questions`, `passed`, `passing_score_threshold` (0.8), `correct_answers` (object mapping question_id to the correct answer for review), and `attempted_at`.
3. IF the `content_id` does not correspond to existing training content, THEN THE Quiz_API SHALL return HTTP 404 with detail "Training content not found: {content_id}".
4. IF the training content has a status other than "approved", THEN THE Quiz_API SHALL return HTTP 400 with detail "Quiz is not available: training content is not in approved status".
5. IF the `answers` object is missing question_ids that exist in the training content quiz, THEN THE Quiz_Service SHALL treat missing answers as incorrect (score 0 for those questions).
6. IF the `answers` object contains question_ids that do not exist in the training content quiz, THEN THE Quiz_Service SHALL ignore those extraneous answers and not count them toward the score or total.
7. IF the request body is missing any required field (`content_id`, `user_id`, or `answers`) or any field fails type validation, THEN THE Quiz_API SHALL return HTTP 422 with a validation error response indicating which fields are invalid.
8. IF the `user_id` does not correspond to an existing user in the system, THEN THE Quiz_API SHALL return HTTP 404 with detail indicating that the user was not found.

### Requirement 3: Quiz Results API Endpoint

**User Story:** As a user, I want to retrieve my quiz attempt history for a specific training content, so that I can review my past scores and verify my pass status.

#### Acceptance Criteria

1. WHEN a user requests quiz results, THE Quiz_API SHALL accept a GET request to `/api/training/quiz/results/{content_id}` with a query parameter `user_id` (integer, required) and return an HTTP 200 response containing a JSON object with a `results` list of all `QuizAttempt` records for that user and content_id (ordered by `attempted_at` descending, most recent first, limited to the 50 most recent attempts) and a top-level `has_passed` boolean field.
2. Each entry in the `results` list SHALL contain: `attempt_id` (integer), `score` (integer), `total_questions` (integer), `passed` (boolean), `attempted_at` (ISO 8601 datetime string with timezone), and `answers` (object mapping question_id strings to the user's selected answer strings for that attempt).
3. THE `has_passed` field SHALL be true if and only if at least one `QuizAttempt` record exists for the given user and content_id where `passed` is true, regardless of whether that attempt falls within the 50-result display limit.
4. IF no quiz attempts exist for the given user and content_id, THEN THE Quiz_API SHALL return HTTP 200 with an empty `results` list and `has_passed` set to false.
5. IF the `user_id` query parameter is missing or is not a valid integer, THEN THE Quiz_API SHALL return HTTP 422 with a validation error message indicating the parameter constraint that was violated.

### Requirement 4: Quiz Pass Verification API Endpoint

**User Story:** As a system, I want a lightweight endpoint to check if a user has passed the quiz for a specific training content, so that the frontend gate guard and task completion flow can verify quiz status efficiently.

#### Acceptance Criteria

1. WHEN a GET request is made to `/api/training/quiz/passed/{content_id}` with a query parameter `user_id` (positive integer, required), THE Quiz_API SHALL return HTTP 200 with a JSON response containing: `content_id` (string), `user_id` (integer), `has_passed` (boolean), and `best_score` (integer or null if no attempts exist).
2. THE `has_passed` field SHALL be true if and only if at least one `QuizAttempt` record exists for the given user and content_id where `passed` is true.
3. THE `best_score` field SHALL contain the highest `score` value among all attempts for the given user and content_id, or null if no attempts exist.
4. IF the `user_id` query parameter is missing or is not a positive integer, THEN THE Quiz_API SHALL return HTTP 422 with a detail message indicating the validation error.
5. IF no `QuizAttempt` records exist for the given user and content_id (including when the content_id does not correspond to any existing training content), THEN THE Quiz_API SHALL return HTTP 200 with `has_passed` set to false and `best_score` set to null.

### Requirement 5: Backend Task Completion Guard (Quiz Prerequisite)

**User Story:** As a system, I want to prevent users from marking a training task as complete until they have passed the associated quiz, so that compliance enforcement cannot be bypassed.

#### Acceptance Criteria

1. WHEN a user attempts to complete a training task via `POST /api/training/tasks/{task_id}/complete`, THE Training_Service SHALL first perform existing validations (task exists, assigned to user, not already completed), THEN verify that the user has passed the quiz for the associated training content (content_id derived as `{sop_document_uuid}_v{sop_version}` from the task) before marking the task complete.
2. IF the user has not passed the quiz (no `QuizAttempt` record with `passed` equal to true exists for the user and derived content_id), THEN THE Training_Service SHALL return HTTP 400 with detail "Cannot complete training task: quiz has not been passed. Please pass the comprehension quiz before marking this task as complete."
3. IF the training content does not exist for the derived content_id (content has not been generated yet), THEN THE Training_Service SHALL return HTTP 400 with detail "Cannot complete training task: training content and quiz are not yet available for this SOP version."
4. IF the user has passed the quiz (verified using the same `user_id` provided in the completion request), THEN THE Training_Service SHALL proceed with the existing task completion flow (mark task complete, create TrainingRecord, check auto-transition).
5. IF the task's `sop_document_uuid` or `sop_version` fields are empty or null (making content_id derivation impossible), THEN THE Training_Service SHALL return HTTP 400 with detail "Cannot complete training task: SOP reference information is missing from this task."

### Requirement 6: Enhanced Training Gate (Backend)

**User Story:** As a system, I want the backend training gate to verify both task completion AND quiz pass status, so that the access control enforcement is comprehensive and cannot be circumvented.

#### Acceptance Criteria

1. WHEN the `check_training_gate` method is invoked, THE Training_Service SHALL verify that the user holds a valid `TrainingRecord` (where `is_valid` is true) for the specified SOP version AND that the user has at least one `QuizAttempt` record with `passed` equal to true for the corresponding content_id (derived as `{sop_document_uuid}_v{sop_version}`).
2. IF the user has a valid TrainingRecord but no `QuizAttempt` record with `passed` equal to true exists for the derived content_id, THEN THE Training_Service SHALL raise HTTP 403 with detail "Action denied: Valid training record exists but quiz for {SOP_Name} Version {sop_version} has not been passed."
3. IF the user has no valid TrainingRecord for the specified SOP version (regardless of quiz pass status), THEN THE Training_Service SHALL raise HTTP 403 with detail "Action denied: Valid training record for {SOP_Name} Version {sop_version} is missing."
4. IF the user has both a valid TrainingRecord and at least one `QuizAttempt` record with `passed` equal to true for the derived content_id, THEN THE Training_Service SHALL allow the action to proceed without raising an exception.
5. WHEN resolving {SOP_Name} for error messages, THE Training_Service SHALL look up the document title by `sop_document_uuid`; IF no document is found, THEN THE Training_Service SHALL use the `sop_document_uuid` value as the SOP_Name in the error detail.

### Requirement 7: Frontend Quiz Taking UI

**User Story:** As a user, I want an interactive quiz interface within the training content viewer, so that I can answer comprehension questions and demonstrate my understanding of the SOP.

#### Acceptance Criteria

1. WHEN the user views approved training content that contains quiz questions, THE Quiz_Taking_UI SHALL display a "Take Quiz" button below the quiz questions section in the Training_Content_Viewer.
2. WHEN the user clicks "Take Quiz", THE Quiz_Taking_UI SHALL present all quiz questions in a sequential form layout, with each question displaying the question text and answer options as radio buttons (the correct_answer mixed with distractors in a randomized order determined once when the quiz is started).
3. THE Quiz_Taking_UI SHALL require the user to select an answer for every question before enabling the "Submit Quiz" button. THE Quiz_Taking_UI SHALL display a progress indicator showing "{answered_count} of {total_questions} answered".
4. WHEN the user clicks "Submit Quiz", THE Training_Store SHALL send a POST request to `/api/training/quiz/submit` with the content_id, user_id, and answers object (mapping question_id to the selected answer string), with the `X-Change-Reason` header set to "Quiz attempt submitted".
5. WHILE the quiz submission is in progress, THE Quiz_Taking_UI SHALL display a loading indicator on the submit button and disable the submit button to prevent duplicate submissions.
6. WHEN the quiz submission returns a successful response, THE Quiz_Taking_UI SHALL display a results panel showing: the score as "{score}/{total_questions}", the pass/fail status with appropriate styling (green for pass, red for fail), and for each question whether the user's answer was correct or incorrect with the correct answer revealed for incorrect responses.
7. IF the user passes the quiz (response `passed` is true), THEN THE Quiz_Taking_UI SHALL display a success message "Quiz passed! You may now mark this training task as complete." and enable the "Mark Complete" button on the associated Training_Task_Card.
8. IF the user fails the quiz (response `passed` is false), THEN THE Quiz_Taking_UI SHALL display a failure message "Quiz not passed. You need at least 80% correct answers. Please review the training material and try again." and provide a "Retake Quiz" button that resets the quiz form to allow another attempt.
9. IF the quiz submission fails due to a network or server error, THEN THE Quiz_Taking_UI SHALL display an error message with a retry button, retain the user's selected answers, and re-enable the submit button.
10. IF the user has already passed the quiz for the current content_id (verified via the Training_Store quizPassCache), THEN THE Quiz_Taking_UI SHALL display a "Quiz Passed" badge with the best score instead of the "Take Quiz" button, and SHALL NOT require the user to retake the quiz.
11. IF the quiz submission fails with HTTP 400 (content not approved) or HTTP 404 (content not found), THEN THE Quiz_Taking_UI SHALL display the error detail from the response body and SHALL NOT provide a retry button (since retrying would produce the same error).

### Requirement 8: Frontend Task Completion Guard (Quiz Prerequisite)

**User Story:** As a user, I want the "Mark Complete" button to be disabled until I pass the quiz, so that I understand the requirement and cannot accidentally attempt completion without passing.

#### Acceptance Criteria

1. WHILE the user has not passed the quiz for the training content associated with a task, THE Training_Task_Card SHALL display the "Mark Complete" button in a disabled state with a tooltip stating "Pass the quiz to enable task completion".
2. WHEN the Training_Store quiz pass status for the current task's content_id changes from false to true (after a successful quiz submission or a fresh pass check), THE Training_Task_Card SHALL enable the "Mark Complete" button and remove the disabled tooltip.
3. WHEN the Training_Content_Viewer loads for a selected task, THE Training_Store SHALL check the quiz pass status by calling `GET /api/training/quiz/passed/{content_id}?user_id={current_user_id}` and cache the result in the quizPassCache keyed by content_id.
4. IF the quiz pass check fails due to a network error, THEN THE Training_Task_Card SHALL keep the "Mark Complete" button disabled and display an inline error icon adjacent to the button with a "Retry" button that re-invokes the `checkQuizPassed` action in the Training_Store for the same content_id and user_id.
5. WHILE the quiz pass status check is in-flight (isCheckingQuizPass is true for the task's content_id), THE Training_Task_Card SHALL display the "Mark Complete" button in a disabled state with a loading spinner in place of the tooltip text.

### Requirement 9: Enhanced Frontend Training Gate Guard

**User Story:** As a system, I want the frontend Training Gate Guard to verify both task completion AND quiz pass status before allowing document access, so that the UI accurately reflects the backend enforcement.

#### Acceptance Criteria

1. WHEN a user navigates to a route for a document whose SOP is in "InTraining" status, THE Training_Gate_Guard SHALL check both: (a) whether the user has a completed training task for the SOP version (via existing Training_Store gate logic), AND (b) whether the user has passed the quiz for the corresponding content_id (via the Training_Store `checkQuizPassed` action using content_id derived as `{sop_document_uuid}_v{sop_version}`).
2. IF the user has completed the training task but has not passed the quiz, THEN THE Training_Gate_Guard SHALL block navigation and display the message "Action denied: Comprehension quiz for {SOP_Name} Version {version} has not been passed. Complete the quiz to gain access."
3. IF the user has not completed the training task (regardless of quiz status), THEN THE Training_Gate_Guard SHALL block navigation and display the existing message "Action denied: Valid training record for {SOP_Name} Version {version} is missing."
4. IF the user has both a completed training task AND a passing quiz attempt, THEN THE Training_Gate_Guard SHALL allow navigation to proceed and render the child route content.
5. THE Training_Gate_Guard SHALL cache the combined gate result (task completion AND quiz pass) in the Training_Store gate cache keyed by `{sop_document_uuid}_v{sop_version}`, invalidating the cache entry via store subscription when either a task is completed (Training_Store task completion action succeeds) or a quiz is passed (Training_Store `submitQuiz` action returns `passed` equal to true) for the corresponding SOP version.
6. IF the Training_Gate_Guard fails to retrieve task completion status or quiz pass status due to a network or server error, THEN THE Training_Gate_Guard SHALL block navigation, display an error message indicating that access verification could not be completed, and provide a retry action that re-triggers the gate evaluation.

### Requirement 10: Training Store Extensions for Quiz State

**User Story:** As a developer, I want the Training Store to manage quiz attempt state and quiz pass verification, so that quiz-related data flows consistently across components.

#### Acceptance Criteria

1. THE Training_Store SHALL maintain additional state for: quiz attempts (currentQuizAttempt, isSubmittingQuiz, quizSubmitError), quiz results (quizResults mapping content_id to list of attempts, isLoadingQuizResults, quizResultsError), and quiz pass status (quizPassCache mapping content_id to boolean, isCheckingQuizPass, quizPassError).
2. THE Training_Store SHALL expose actions for: submitQuiz(contentId, userId, answers), fetchQuizResults(contentId, userId), checkQuizPassed(contentId, userId), and clearQuizPassCache().
3. WHEN submitQuiz is called, THE Training_Store SHALL skip execution if isSubmittingQuiz is already true (request deduplication), set isSubmittingQuiz to true, clear quizSubmitError, send a POST request to `/api/training/quiz/submit` with the content_id, user_id, and answers in the body and "Quiz attempt submitted" in the `X-Change-Reason` header, store the response in currentQuizAttempt on success, update the quizPassCache entry for the content_id to true if the attempt passed, invalidate the gate cache for the corresponding sop_document_uuid and sop_version, and set isSubmittingQuiz to false.
4. IF the submitQuiz request fails, THEN THE Training_Store SHALL set quizSubmitError to the error message extracted via the extractErrorMessage utility and set isSubmittingQuiz to false.
5. WHEN checkQuizPassed is called, THE Training_Store SHALL first check the quizPassCache for an existing entry for the given content_id. IF a cached entry exists, THEN THE store SHALL return the cached boolean value without making a network request. IF no cached entry exists, THEN THE store SHALL skip execution if isCheckingQuizPass is already true (request deduplication), set isCheckingQuizPass to true, clear quizPassError, send a GET request to `/api/training/quiz/passed/{contentId}?user_id={userId}`, store the `has_passed` value from the response in the quizPassCache keyed by content_id, set isCheckingQuizPass to false, and return the `has_passed` value.
6. IF the checkQuizPassed GET request fails, THEN THE Training_Store SHALL set quizPassError to the error message extracted via the extractErrorMessage utility, set isCheckingQuizPass to false, and return null to signal that pass status is unknown.
7. WHEN fetchQuizResults is called, THE Training_Store SHALL skip execution if isLoadingQuizResults is already true (request deduplication), set isLoadingQuizResults to true, clear quizResultsError, send a GET request to `/api/training/quiz/results/{contentId}?user_id={userId}`, store the response list in quizResults keyed by content_id, and set isLoadingQuizResults to false. IF the request fails, THEN THE store SHALL set quizResultsError to the error message extracted via the extractErrorMessage utility and set isLoadingQuizResults to false.
8. WHEN the Training_Store gate cache is invalidated for a specific sop_document_uuid and sop_version (on task completion or quiz pass), THE Training_Store SHALL also invalidate the corresponding quizPassCache entry for the derived content_id (formatted as `{sop_document_uuid}_v{sop_version}`).
9. WHEN clearQuizPassCache is called, THE Training_Store SHALL reset the quizPassCache to an empty mapping, set quizPassError to null, and set isCheckingQuizPass to false.

### Requirement 11: Quiz Attempt Audit Trail

**User Story:** As a compliance officer, I want all quiz attempts (both passed and failed) to be recorded in the audit trail, so that training compliance can be verified during regulatory audits.

#### Acceptance Criteria

1. WHEN a quiz attempt is submitted, THE Quiz_Service SHALL record the Quiz_Attempt record as the audit event, persisting the following fields: user_id, company_id, content_id, sop_document_uuid, sop_version, score, total_questions, passed status, and attempted_at timestamp.
2. THE Quiz_Attempt records SHALL be immutable after creation. IF a request attempts to update or delete a Quiz_Attempt record via the Quiz_API, THEN THE Quiz_API SHALL return HTTP 405 (Method Not Allowed) with detail "Quiz attempt records are immutable and cannot be modified or deleted."
3. WHEN a user passes the quiz after one or more failed attempts, THE audit trail SHALL preserve all previous failed attempts alongside the passing attempt, providing a complete history of the user's quiz interactions queryable via the Quiz Results API endpoint.

### Requirement 12: Training Content Version Invalidation for Quiz

**User Story:** As a system, I want quiz pass status to be invalidated when training content is updated for a new SOP version, so that users must re-take the quiz for updated material.

#### Acceptance Criteria

1. WHEN a new SOP version triggers training content regeneration (new content_id is created for the new version), THE Training_Gate_Guard SHALL deny access to the new version for users who only hold a quiz pass for the previous version's content_id, requiring a new passing quiz attempt against the new content_id.
2. WHEN previous training records are invalidated (via `invalidate_previous_training_records`), THE Quiz_Service SHALL evaluate quiz pass status exclusively by matching the content_id derived from the current SOP version (`{sop_document_uuid}_v{sop_version}`), so that quiz passes recorded against a prior version's content_id do not satisfy the gate check for the new version.
3. THE Training_Gate_Guard SHALL verify quiz pass status against the exact content_id derived from the current SOP version being accessed, using the format `{sop_document_uuid}_v{sop_version}` to construct the lookup key.
4. WHEN a new SOP version is published and new training content is generated, THE Training_Store SHALL invalidate any quizPassCache entries associated with the previous version's content_id for that SOP document, so that subsequent gate checks fetch fresh quiz pass status from the backend.
